# Как написать плагин для Mouvi (`.mu`)

Этот документ описывает формат плагинов Mouvi, манифест, доступные хуки и сборку `.mu` через `mouvi-builder`.

> **Важно (MVP):** сейчас в приложении реально исполняется декларативная часть хука `importValidation` (правила распознавания конфигов в `importRules`). Остальные хуки и типы плагинов (движки, события соединения, UI/URI, произвольный исполняемый код из пакета) заложены в манифест/реестр как контракт и основа для следующих версий — их runtime-исполнение пока не реализовано.

## Что такое `.mu`
`.mu` (**Mouvi Universal**) — это ZIP-архив с плагином. Минимальное содержимое — файл `manifest.json` в корне архива. Внутри также могут находиться исходный код, ресурсы, нативные библиотеки, документация и любые другие файлы плагина.

Пример структуры:
```
my-plugin/
├── manifest.json        # обязательно
├── README.md            # опционально
├── icon.png             # опционально
├── src/                 # ваш код/скрипты (опционально)
└── assets/              # ресурсы (опционально)
```

## Быстрый старт

### 1. Создать шаблон
Из корня репозитория Mouvi (нужен установленный Dart/Flutter SDK):

```bash
# Linux/macOS
./mouvi-builder init ./my-plugin --id com.example.myplugin --name "My Plugin"

# Windows
mouvi-builder.bat init .\my-plugin --id com.example.myplugin --name "My Plugin"

# или напрямую через Dart
dart run tool/mouvi_builder.dart init ./my-plugin --id com.example.myplugin --name "My Plugin"
```

### 2. Отредактировать `manifest.json` и добавить файлы
Настройте манифест и положите в папку код/ресурсы плагина.

### 3. Проверить и собрать `.mu`
```bash
./mouvi-builder validate ./my-plugin
./mouvi-builder build ./my-plugin -o ./my-plugin.mu
```

По умолчанию (без `-o`) файл будет создан как `<id>-<version>.mu` в текущей директории.

### 4. Установить в приложение
Mouvi → **Настройки → Плагины → (＋) Установить плагин** → «Установить из файла» и выберите `.mu`.
Также поддерживается установка по URL и из каталога магазина.

## `mouvi-builder` (CLI)

```text
Usage:
  dart run tool/mouvi_builder.dart <command> [options]
  ./mouvi-builder <command> [options]

Commands:
  build <plugin_dir> [-o <output.mu>]    Упаковать директорию плагина в .mu
  validate <path>                        Проверить manifest (директория или .mu)
  init <dir> [--id <id>] [--name <name>] Создать шаблон плагина
  help                                   Справка
```

- `build` включает в архив все файлы из директории плагина (рекурсивно), `manifest.json` должен быть в корне.
- `validate` проверяет обязательные поля, формат `id` и совместимость `apiVersion`.

## Манифест (`manifest.json`)

Минимальный пример:
```json
{
  "id": "com.vendor.myplugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "apiVersion": 1,
  "author": "Author Name",
  "description": "Короткое описание плагина.",
  "permissions": ["ownStorage", "connectionState"],
  "hooks": ["importValidation"],
  "importRules": []
}
```

### Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---:|---|
| `id` | string | да | Уникальный идентификатор. Формат: `^[a-zA-Z0-9._-]{1,64}$` (рекомендуется reverse-DNS, напр. `com.example.plugin`). |
| `name` | string | да | Отображаемое имя. |
| `version` | string | да | Версия плагина (рекомендуется semver, напр. `1.0.0`). |
| `apiVersion` | int | да | Версия API плагинов Mouvi. Текущая поддерживаемая: `1`. |
| `author` | string | нет | Автор/издатель. |
| `description` | string | нет | Описание. |
| `minAppVersion` | string | нет | Минимальная версия приложения Mouvi. |
| `homepage` | string | нет | Ссылка на сайт/репозиторий. |
| `permissions` | string[] | нет | Запрашиваемые разрешения (см. ниже). |
| `hooks` | string[] | нет | Точки расширения, которые использует плагин. |
| `importRules` | object[] | нет | Декларативные правила импорта (для `importValidation`). |
| `dependencies` | object | нет | Зависимости/ограничения (`"plugin.id": "versionRange"`), резерв для будущих версий. |

> При установке `apiVersion` плагина не должен превышать поддерживаемый приложением; `id` должен быть валидным. Переустановка пакета с тем же `id` обновляет плагин.

## Разрешения (`permissions`)

| Значение | Смысл |
|---|---|
| `ownStorage` | Собственное изолированное хранилище/настройки плагина. |
| `connectionState` | Доступ к состоянию соединения (без секретов). |
| `trafficStats` | Доступ к статистике трафика. |
| `configsMetadata` | Доступ к метаданным конфигов **без** приватных ключей/секретов. |
| `sensitiveData` | Доступ к чувствительным данным (секреты/ключи) — высокий риск, только при явной необходимости. |
| `manageConnection` | Управление подключением (старт/стоп, выбор/передача конфига). |
| `engineAccess` | Доступ на уровне движка/сетевого стека (полный доступ движка). |
| `uiExtensions` | Расширения интерфейса. |
| `uriHandlers` | Обработка специальных URI/ссылок. |

Разрешения указываются в манифесте для прозрачности и будущего enforcement; запрашивайте минимально необходимый набор.

## Хуки (`hooks`)

| Хук | Назначение |
|---|---|
| `importValidation` | Распознавание, парсинг и валидация новых форматов конфигов. **(MVP: поддержаны декларативные `importRules`)** |
| `engineProvider` | Регистрация протокола/движка и участие в подключении. *(контракт, runtime в разработке)* |
| `connectionEvents` | События жизненного цикла: до/после подключения, отключение, ошибки, смена сети. *(контракт)* |
| `uiExtensions` | Экраны/действия/элементы UI. *(контракт)* |
| `uriHandlers` | Обработка URI/ссылок. *(контракт)* |

## Декларативный импорт: `importRules` (работает в MVP)

Позволяет плагину распознавать конфиги без исполнения произвольного кода. Если встроенный парсер Mouvi не распознал конфиг, активный плагин с `importValidation` может сопоставить его по правилам и дать импортировать (как конфиг, распознанный плагином).

```json
"hooks": ["importValidation"],
"importRules": [
  {
    "id": "my-rule",
    "label": "My Protocol",
    "uriSchemes": ["myproto://"],
    "containsAll": ["[Interface]", "MyTag"],
    "containsAny": ["[MySection]"],
    "regex": "^myproto://.+"
  }
]
```

Поля правила:
- `id` — идентификатор правила (строка).
- `label` — метка, показываемая при импорте.
- `uriSchemes` — список схем/префиксов URI (напр. `myproto://`).
- `containsAll` — совпадение, если текст содержит **все** подстроки (без учёта регистра).
- `containsAny` — совпадение, если текст содержит **любую** из подстрок.
- `regex` — регулярное выражение (без учёта регистра, многострочный режим).

Достаточно срабатывания любого из заданных условий.

## Базовый плагин `mouvi-engine`

`mouvi-engine` — встроенный системный плагин Mouvi. Он всегда присутствует и не может быть удалён. Его можно отключить, но **при отключённом `mouvi-engine` все остальные плагины становятся неактивными** (их хуки не применяются). Это механизм глобального выключателя плагинной системы.

## Источники, магазин и безопасность

- **Официальный источник:** плагины из репозитория/каталога `bitplugg/mouvi-store` считаются официальными.
- **Сторонние плагины** (локальный файл, произвольный URL, не `mouvi-store`) перед включением/активацией требуют явного подтверждения диалогом с текстом: **«Я согласен со всеми рисками»**. Факт согласия сохраняется для установленного плагина.
- Устанавливайте плагины только из доверенных источников: плагин может влиять на поведение приложения в рамках заявленных возможностей.
- Криптографическая подпись пакета как обязательная проверка в текущем MVP не применяется; ориентируйтесь на источник и проверку содержимого.

### Каталог магазина
Приложение загружает индекс `index.json` из `https://raw.githubusercontent.com/bitplugg/mouvi-store/master/index.json`.
Формат индекса:
```json
{
  "plugins": [
    {
      "id": "com.example.plugin",
      "name": "Plugin Name",
      "version": "1.0.0",
      "description": "Описание",
      "downloadUrl": "https://.../plugin.mu"
    }
  ]
}
```

## Установка, обновление и хранение

- **Установка:** из файла (`.mu`) или по URL. Повторная установка того же `id` обновляет плагин (с сохранением состояния включения/согласия, где применимо).
- **Включение/выключение:** переключатель в списке плагинов; для сторонних — с подтверждением рисков при первом включении.
- **Удаление:** доступно для всех, кроме `mouvi-engine`.
- Пакеты распаковываются во внутреннее хранилище приложения (`plugins/<id>/`), метаданные ведутся приложением. У каждого плагина предусматривается собственное изолированное хранилище (по разрешению `ownStorage`).

## Включение кода/ресурсов в `.mu`

`mouvi-builder build` упаковывает **все файлы** из директории плагина в `.mu` (ZIP). Вы можете включать:
- исходный код (Dart, Kotlin/Java, скрипты) и документацию;
- ресурсы (иконки, JSON, текст);
- нативные библиотеки (`.so` и т.п.) и другие артефакты — для будущей поддержки нативных/движковых плагинов.

Расположение и точка входа исполняемого кода будут определяться контрактом соответствующего хука (напр. поле `entry`/конфигурация движка) по мере реализации runtime. В текущем MVP исполняются декларативные правила из манифеста.

## Эталонный пример

В репозитории: `examples/plugins/hello-import.mu` (и исходный `hello-import-manifest.json`, `README.md`).
Он демонстрирует хук `importValidation` с правилами для `mouvi-example://` и маркера `[MouviExample]`.

Тест: установите `hello-import.mu`, включите плагин (подтвердите риски — пример не из store) и импортируйте конфиг:
```text
mouvi-example://demo#Example
```
или
```text
[MouviExample]
name=demo
```

## Рекомендации
- Используйте уникальный `id` в стиле reverse-DNS.
- Запрашивайте минимум разрешений и явно указывайте нужные хуки.
- Повышайте `version` при каждом выпуске; следите за `apiVersion`/`minAppVersion`.
- Проверяйте пакет перед публикацией: `./mouvi-builder validate <dir|file.mu>`.
- Для распространения через официальный каталог публикуйте `.mu` и добавляйте запись в `index.json` репозитория `bitplugg/mouvi-store`.
